# Provider

Providers are designed to be reusable components that serve as the foundational data sources that Adaptors can then build upon, transform, and combine. They encapsulate the details of connecting to external data sources and standardize the way data is fetched and formatted within the ADCS system.

## How to become a provider

**1. Fork github repo.**

You need to fork our adcs repo [here](https://github.com/Rivalz-ai/ADCS-core)

**2. Fill out information about your provider**

- You can find the template json file [here](https://github.com/Rivalz-ai/ADCS-core/tree/42-redefine-provider/open/providers).

- Create new file from the template and fill out your provider information

Provider's structure and description here

```json
{
  "id": "id of the provider",
  "name": "provider name",
  "description": "description for provider",
  "icon_url": "icon url",
  "methods": [
    {
      "method_name": "method 1",
      "description": "description for method 1",
      "input_schema": { "key": "value" },
      "input_type": "QueryParams|BodyParams",
      "output_schema": { "key": "value", "key2": "value2" },
      "type": "GET|POST",
      "playground": "playground url"
    },
    {
      "method_name": "method 2",
      "description": "description for method 2",
      "input_schema": { "key": "value" },
      "input_type": "QueryParams|BodyParams",
      "output_schema": { "key": "value", "key2": "value2" },
      "type": "GET|POST",
      "playground": "playground url"
    }
  ]
}
```

- `id`: id of the provider. This is unique and generated by the system, you dont need to specify it.
- `name`: The provider name to show on web application
- `description`: Detail description about the provider, should include the purpose of the provider, type of data, etc.
- `icon_url`: The icon of the provider to show on our web application
  - Recommend to use svg format for the icon
  - size: 100x100px
- `methods`: List of methods
  - `method_name`: The method name of the provider
  - `description`: Describe about the method, what data is provided by this method
  - `type`: GET/POST method for the method
  - `input_schema`: Json object. For example: `{"coinName":"Btc"}`
    - only one key-value pair
  - `input_type`: using query params or body data
  - `output_schema`: Json object. For example: `{"price":"1000", "timestamp":"1712982400"}`
    - multiple key-value pairs
  - `playground`: This playground is implemented by ADCS to playaround with the provider.

⚠️ **Important Notes**

- Only one key-pair value is currently supported in the `input_schema`
- Nested objects are not supported at this time

**3. Raise PR.**

Commit and raise PR for your change.

**4. Fill in the Provider submission form.**

Go to this [link] and provide us the following information
- API endpoint: the URL to you endpoint. example: https://api.github.com/repos/openai/gym
- API key: You should provide the key name and key value to access the endpoint. example: {"key_name": "github_api_key", "key_value": "ghp_1234567890"}
- Github PR: the link to you Pull Request
- Json URL: the link to your definition file. example: https://github.com/Rivalz-ai/ADCS-core/blob/main/inference/descriptions.json
- Document link (optional): If you have documentation about your provider, you can provide the link here.
- Playground: After you fill in the above information, we will generate the playground for you to test and verify your provider.
 - Method: Select the method you want to test
 - Input: Fill in the parameter for the selected method
 - click the verify button to test your provider
- If the result is successful, you can submit your provider
